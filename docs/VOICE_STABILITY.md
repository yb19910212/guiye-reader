# v0.14.0 语音稳定性与 Qwen iOS 实验版

## 已实现

- 原 Kokoro 模型、四款中文女声、两款英文女声和系统音色保留。
- iOS 新增 `qwen:gentle`（用户选定 1号）、`qwen:coaxing`（4号）。使用原始 WAV 作为声音参考，对任意新正文做 Base-model conditioning，而非重复播放试听录音。
- iOS 18+；Qwen 0.6B Base 4bit 资源固定 revision 与权重 SHA-256，构建时打包，运行时不下载、不上传正文。Android 暂不接入 Qwen，经用户确认。
- 两端正文惰性切分为最多 48 字符左右的片段；保留段落 ID，中文标点优先作为边界。
- 当前片段加最多两个后续片段的生成窗口。暂停不丢缓存；停止/切换使旧会话失效。
- Kokoro 在计算前和生成回调中检查取消；Qwen 每个生成步检查取消。取消是协作式，不能承诺即时停止正在执行的 GPU 运算或模型初始化。
- 两端过滤过期系统语音及播放器回调，避免旧队列推进新队列；语速变更 350ms 防抖。
- Android 使用单个应用级 Kokoro 实例，不在视图关闭时销毁正在使用的 native pointer。
- iOS 在同一后台队列运行两种模型，换引擎时先卸载旧实例，模型文件不会删除；Qwen GPU 回收缓存限制为 32MB。内存警告会停止语音并安排卸载。
- Qwen 实验版限定前台使用，willResignActive 时取消任务并停止播放，避免后台 Metal 计算。锁屏听书保留原有引擎。

## 测试边界

- Windows：Kotlin 编译实际 SpeechEngine.kt 并运行 JUnit，3 项测试通过（文字/Unicode 保留、起点/空输入、10000 个片段的窗口上限）。
- macOS CI：Swift 实际 SpeechEngine.swift 的切分、窗口和取消对象回归检查已通过。
- 编译与资源验证不代表 iPhone 连续播放或音质验收通过。
- 没有取得用户设备的 crash / jetsam 日志。所做修复覆盖代码中发现的风险，不能宣称已确认或消除全部闪退原因。
- Qwen 手机量化 Base 模型与桌面试听的 1.7B VoiceDesign 不同；声音相似度、发热、速度必须重新验收。

## 发布前后真机验收表（待完成）

1. 飞行模式下分别播放系统本地语音、Kokoro、Qwen 1号和4号；Qwen 需至少6GB物理内存，但该门槛不保证可用内存充足。
2. 连续快速切换各引擎/音色 50 次、拖动语速、停止后立即退出阅读页；不得出现旧音频复活、越界或闪退。
3. 在生成中、准备播放中、播放中分别暂停/恢复，段落进度应与实际播放一致。
4. 用长段落、中英混排、大书连续听30分钟，记录首音、切换延迟、段间空白、内存峰值和发热。
5. 锁屏/后台测试需要单独进行；不能因后台持续播放承诺就忽略 Metal 在后台的执行限制。
6. 若生成速度低于播放速度，预生成无法保证无空白；应使用较轻的原模型或后续章节预生成方案。

当前作为实验预发布，原稳定版本继续保留供回退。

# v0.16.0 章节语音缓存

## 使用
选择远程 API 音色，打开 TXT 的目标章节，点击“缓存本章后播放 / 重试”（Android：“缓存本章 / 重试”）。只发送当前章节，全部缓存完成后自动开始。普通“开始朗读”仍是边生成边听，服务器慢时会等待。
请保持应用前台；本版本不承诺后台持续下载。取消后保留已完成缓存，重新操作同一章节会复用。缓存属于可清理数据，操作系统清理缓存、卸载应用后可能丢失。

## 实现边界
- 断句上限 80 个字符；超长段落优先在句末、其次分句标点切开，无标点才硬切。不会丢失正文或段落 ID。
- 单章最多 1000 个音频段，超出则提示改用逐段朗读。单文件最大 8 MB，总缓存上限 200 MB；满后提示手动清理。
- 队列保存文件地址，不把整章音频保留在内存。语音音频及密钥不进备份清单。
- 缓存键包含断句版本、模型、服务地址、账号密钥、音色、正文的 SHA-256；不包含播放倍速。文件名不含明文书籍或密钥。
- 完整 WAV 校验通过后原子保存。该校验只能发现文件不完整/不兼容，不能保证模型没有漏读、提前结束。
- 当前服务返回整段 WAV，没有单句内部进度。因此显示完成段数、缓存命中、请求计时、准备均速和播放器时间，不模拟生成百分比。
- 准备均速包含缓存命中、服务等待及下载，不等同于网络速度或纯模型推理速度。
- 本次没有修改 NAS 模型、PVE 或飞牛。首次生成速度仍由服务器决定。缓存准备好后不再逐段等待生成，但播放器切段仍可能有短暂间隙。

## 自动化与验收
双端测试包含：Unicode/文本重组不丢失、70 字句子保留、队列上限、有效 WAV、截断 WAV 拒绝、磁盘缓存重建后读取、音色键隔离和缓存清理。
GitHub Actions 运行 iOS Swift 回归、Android 单元测试、双端构建及轻量包检查。

仍需真机验收：
1. 1号/4号分别缓存三段文本，计时持续更新，完成后逐段播放。
2. 取消后重试、强制退出再打开同一章，已完成段显示缓存命中。
3. 缓存完毕后断网播放；变速不触发新请求。
4. 等待/播放中暂停与恢复、换音色、换章节、清理缓存，旧任务不能接着播放。
5. 401、429、断网、服务超时、存储空间不足给出可重试错误，正文仍可滚动。
6. iPhone 17 Pro Max 与 Android 真机长章节、锁屏、前后台及音频尾句人工核验。
